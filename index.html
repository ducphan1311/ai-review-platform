Hỗ Trợ 5 Cơ Chế Định Nghĩa Rule Linh Hoạt

Được thiết kế theo tiêu chuẩn của arch-rules-engine: Bạn có thể tự viết rule mới trong file cấu hình YAML mà không cần sửa bất kỳ dòng mã nguồn nào của engine.

1

layer_boundary (Phân Tầng Kiến Trúc)

Duyệt toàn bộ Import Graph và cấu trúc thư mục. Ngăn chặn triệt để việc tầng Domain phụ thuộc vào Presentation/UI hoặc Data. 

- id: "RULE_CLEAN_DOMAIN"
  type: "layer_boundary"
  source_layer: "domain"
  forbidden_target_layers: ["presentation", "data"]
  severity: "BLOCKER"
2

forbidden_calls (Cấm Gọi Hàm Bất Kỳ)

Duyệt AST phân tích các method call. Cấm dùng print, debugPrint, eval() hoặc gọi trực tiếp Database trong UI. 

- id: "BAN_PRINT_ON_PROD"
  type: "forbidden_calls"
  calls: ["print", "debugPrint"]
  scope: ["lib/**/*.dart"]
  severity: "BLOCKER"
3

ast_pattern (Bắt Mẫu Cú Pháp AST)

Tích hợp sẵn các anti-pattern phổ biến như empty_catch_block, await_before_setstate, missing_mounted_check. 

- id: "ASYNC_MOUNTED_GUARD"
  type: "ast_pattern"
  pattern_name: "await_before_setstate"
  severity: "CRITICAL"
4

meta_pattern (Semgrep AST Metavariables)

Tự do định nghĩa mọi pattern phức tạp thông qua các biến đại diện $X, $E, ... mà không cần đụng đến code backend. 

- id: "NO_SILENT_EMPTY_CATCH"
  type: "meta_pattern"
  pattern: "catch ($E) { }"
  severity: "BLOCKER"
5

custom_script (Plugin Script Dự Án Tự Nạp)

Chạy script kiểm tra đặc thù riêng của từng công ty (Quy chuẩn đặt tên file _view.dart, kiểm tra kích thước file, lint nội bộ) và nhận JSON output. 

- id: "CHECK_VIEW_FILE_NAMING"
  type: "custom_script"
  script_path: "scripts/rules/check_naming.sh"
  severity: "WARNING"
