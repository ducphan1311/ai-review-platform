Modular System Design

Mô Hình Kiến Trúc 3 Tầng Độc Lập

Được phân tách theo nguyên tắc Separation of Concerns chặt chẽ: Máy quét tất định giữ cổng chất lượng, AI đóng vai trò cố vấn, và Gateway phụ trách kiểm soát CI/CD.

Project 1 • Hard Gate

arch-rules-engine

Động cơ phân tích tĩnh lõi (AST Engine). Phân tích đồ thị phụ thuộc (Import Graph), duyệt AST syntax tree để phát hiện vi phạm phân tầng Clean Architecture, các lệnh cấm, và anti-pattern vi mô.

  • Xử lý Git Diff (Delta Mode) siêu tốc
  • Hỗ trợ file nợ kỹ thuật baseline.json
  • Quyết định kết quả Pass / Fail tất định
Output: ScanReport.json (Exit 0 / 1 / 2)
Project 2 • Soft Layer

review-agent-service

AI Review Agent cố vấn (Advisory Layer). Nhận báo cáo vi phạm từ Project 1, đóng gói bối cảnh code và kích hoạt LLM phân tích nguyên nhân cốt lõi và viết sẵn code refactor gợi ý.

  • Hỗ trợ mọi LLM (OpenAI, Gemini, Local Ollama)
  • Tuyệt đối không thể đảo ngược Hard Gate
  • Giải thích dễ hiểu theo văn phong tiếng Việt
Output: ReviewResult (Summary & Advisory Diff)
Project 3 • Gatekeeper

integrations-gateway

Cổng giao tiếp CI/CD bảo mật. Tiếp nhận Webhook từ GitHub / GitLab, xác thực License Key Ed25519, điều phối thực thi và đăng tải bình luận kết quả lên Pull Request.

  • Xác thực HMAC SHA-256 Webhook
  • Xác thực chữ ký số bản quyền Ed25519
  • Khóa Merge PR nếu vi phạm BLOCKER
Action: Lock Merge Button & Post PR Comment
Execution Pipeline

Luồng Code Chạy Step-by-Step Khi Kiểm Tra PR

Mỗi khi lập trình viên tạo hoặc cập nhật Pull Request, chuỗi xử lý diễn ra tự động qua 4 bước:

// SƠ ĐỒ ĐIỀU PHỐI TỔNG QUAN
[ Developer tạo Pull Request trên GitHub / GitLab ]
│
▼
[ 1. HARD GATE: arch-rules-engine ]
├─ Lấy Git Diff (Delta Mode) & quét import AST cây mã nguồn
└─ So sánh với quy tắc kiến trúc architecture_rules.yaml
│
├── [ KHÔNG CÓ LỖI ] ──────► [ Quality Gate: PASSED ✅ ] ──► Mở Cổng Cho Phép Merge
│
└── [ CÓ LỖI BLOCKER / WARNING ]
│
▼
[ 2. AI ADVISORY AGENT: review-agent-service ]
├─ Tổng hợp bằng chứng lỗi vi phạm (File, Dòng, Tên luật)
└─ Gọi LLM phân tích nguyên nhân kiến trúc & sinh Code Refactor đề xuất
│
▼
[ 3. GATEWAY PHÁN QUYẾT: integrations-gateway ]
├─ Đóng cổng Merge (Quality Gate: FAILED ❌)
└─ Đăng báo cáo phân tích chi tiết & code diff lên bình luận PR
1

Lấy Git Diff (Chế Độ Delta Checker)

Thay vì quét lại toàn bộ hàng nghìn file từ đầu gây chậm trễ CI/CD, hệ thống thực thi lệnh git diff --name-only origin/main để lấy chính xác danh sách các file được thêm mới hoặc chỉnh sửa trong PR này.

2

Phân Tích Cú Pháp AST & Xây Dựng Đồ Thị

Bộ phân tích cú pháp quét từng dòng mã nguồn, trích xuất tất cả các câu lệnh import, xác định: file nguồn thuộc layer nào, file đích được import thuộc layer nào. Đối chiếu với cấu hình luật để phát hiện ngay các vi phạm phân tầng.

3

Kích Hoạt AI Review Agent

Review Agent đóng gói dữ liệu vi phạm (tên file, số dòng, đoạn code sai, tên luật) gửi sang LLM (OpenAI / Gemini / Ollama). AI phân tích chuyên sâu tại sao lại sai theo góc nhìn kiến trúc phần mềm và viết sẵn code refactor đề xuất bằng tiếng Việt.

4

Integrations Gateway Phán Quyết & Đăng Báo Cáo

Gateway tổng hợp phán quyết: Nếu dính lỗi BLOCKER, tự động set Check Run Conclusion = FAILURE, chặn nút Merge trên GitHub/GitLab, đồng thời đăng tải toàn bộ báo cáo phân tích kèm gợi ý code lên bình luận của PR.

5 Cơ Chế Tự Định Nghĩa Quy Tắc Kiểm Tra

Bạn có thể tự do mở rộng và thêm các quy tắc mới trong file config/architecture_rules.yaml tại repo mục tiêu mà không cần chỉnh sửa bất kỳ dòng mã nguồn nào của engine.

Cơ chế Giá trị type Cơ chế thực thi Bài toán giải quyết
1. Phân Tầng Kiến Trúc layer_boundary Đồ thị Import Graph & Đường dẫn Clean Architecture, cô lập Domain, chống phụ thuộc vòng lặp (Circular Dependency).
2. Cấm Gọi Hàm Bất Kỳ forbidden_calls AST Visitor duyệt tên phương thức Cấm print, debugPrint, eval(), cấm gọi trực tiếp DB/API trong UI.
3. Bắt Cú Pháp AST Có Sẵn ast_pattern Bộ phân tích cú pháp AST dựng sẵn Chống Anti-pattern vi mô: empty_catch_block, await_before_setstate.
4. Mẫu Tự Do Meta-Variable meta_pattern Động cơ Semgrep AST Engine Tự viết mẫu AST bất kỳ bằng ký hiệu $X, $E, ... không cần code.
5. Plugin Script Tự Nạp custom_script Thực thi Process độc lập Quy tắc riêng của từng cty: Quy ước đặt tên file (_view.dart), kích thước asset, linter nội bộ.
Mẫu Cấu Hình: 1. layer_boundary 
- id: "RULE_CLEAN_DOMAIN"
  type: "layer_boundary"
  source_layer: "domain"
  forbidden_target_layers: ["presentation", "data"]
  severity: "BLOCKER"
  description: "Tầng Domain cấm import ngược UI hoặc Data."
  remediation: "Sử dụng Dependency Inversion định nghĩa interface tại Domain."
Mẫu Cấu Hình: 2. forbidden_calls 
- id: "BAN_PRINT_ON_PROD"
  type: "forbidden_calls"
  calls: ["print", "debugPrint"]
  scope: ["lib/**/*.dart"]
  severity: "BLOCKER"
  description: "Cấm in log trực tiếp gây rò rỉ token PII."
  remediation: "Sử dụng AppLogger hoặc Logs.d() thay thế."
Mẫu Cấu Hình: 3. ast_pattern 
- id: "ASYNC_MOUNTED_GUARD"
  type: "ast_pattern"
  pattern_name: "await_before_setstate"
  severity: "CRITICAL"
  description: "Bắt buộc có guard clause sau await trước setState."
  remediation: "Chèn 'if (!mounted) return;' ngay sau await."
Mẫu Cấu Hình: 4. meta_pattern 
- id: "NO_SILENT_EMPTY_CATCH"
  type: "meta_pattern"
  pattern: "catch ($E) { }"
  severity: "BLOCKER"
  description: "Bắt biến ngoại lệ nhưng bỏ trống khối catch."
  remediation: "Ghi log ngoại lệ hoặc xử lý fallback an toàn."

Dưới đây là ca kiểm thử tự động trên repository monorepo thực tế: Hệ thống phát hiện toàn bộ vi phạm và đăng báo cáo trực tiếp.

AI
ai-architecture-bot vừa bình luận trên Pull Request
Quality Gate: FAILED ❌ (Khóa Merge PR)

Danh Sách Vi Phạm Phát Hiện Trực Tiếp Trên PR:

BLOCKER
RULE_CLEAN_DOMAIN lib/config/app_config.dart:3

Tầng 'domain' không được phép import từ tầng 'presentation' (package:fluffychat/pages/chat/chat_view.dart).

BLOCKER
BAN_PRINT_ON_PROD lib/pages/demo_showcase/profile_demo_page.dart:21

Cấm in log print() trực tiếp trên Production gây rò rỉ token PII (secret_token_xyz) và giật UI.

BLOCKER
NO_SILENT_EMPTY_CATCH lib/pages/demo_showcase/profile_demo_page.dart:24

Bắt được biến ngoại lệ $E nhưng bỏ trống khối catch (nuốt exception ngầm gây mất dấu telemetry).

CRITICAL
ASYNC_MOUNTED_GUARD lib/pages/demo_showcase/profile_demo_page.dart:31

Bắt buộc có guard clause if (!mounted) return; sau lệnh await trước khi gọi setState().

WARNING
CHECK_VIEW_FILE_NAMING lib/pages/demo_showcase/profile_demo_page.dart:1

File vi phạm naming convention: widget màn hình phải kết thúc bằng _view.dart thay vì _page.dart.

Hướng Dẫn Sửa Lỗi Chi Tiết (Remediation Diff):

// Khắc phục ASYNC_MOUNTED_GUARD:
- await Future.delayed(Duration(seconds: 2));
- setState(() { status = "completed"; });
+ await Future.delayed(Duration(seconds: 2));
+ if (!mounted) return; // Bảo vệ widget không unmounted
+ setState(() { status = "completed"; });
Deployment Guide

Hướng Dẫn Thiết Lập Cho Repository Mới

Bất kỳ dự án nào (Flutter, iOS, Android, React Native...) chỉ cần 3 bước đơn giản:

1

Khai báo cấu hình architecture_rules.yaml tại thư mục gốc

Tạo file config/architecture_rules.yaml trong repository của bạn:

version: "1.0.0"
monorepo:
  package_dirs: ["lib"]

# 1. Phân tầng kiến trúc Clean Architecture
layers:
  - name: "domain"
    aliases: ["config", "utils", "core"]
    description: "Tầng dữ liệu cốt lõi & logic nghiệp vụ"
  - name: "presentation"
    aliases: ["pages", "widgets", "ui"]
    description: "Tầng giao diện người dùng (UI)"
  - name: "data"
    aliases: ["repository", "network", "datasources"]
    description: "Tầng hạ tầng kết nối DB / API"

# 2. Rào chắn quy tắc kiểm tra
rules:
  - id: "RULE_CLEAN_DOMAIN"
    name: "Domain cấm import UI"
    severity: "BLOCKER"
    source_layer: "domain"
    forbidden_target_layers: ["presentation", "data"]

  - id: "BAN_PRINT_ON_PROD"
    name: "Cấm print trên Production"
    type: "forbidden_calls"
    calls: ["print", "debugPrint"]
    severity: "BLOCKER"

  - id: "RULE_CIRCULAR_DEP"
    name: "Chống phụ thuộc vòng lặp"
    severity: "BLOCKER"
2

Khởi chạy Docker Container với License Key Ed25519

Chạy container trên server nội bộ (On-Premise VM). Container tự động xác thực chữ ký bản quyền số:

docker run -d --name ai-review-service \
  -p 8080:8080 \
  -v /opt/ai-review/license.lic:/app/license.lic:ro \
  -e GITHUB_WEBHOOK_SECRET="your-corporate-secret-at-least-32-chars" \
  -e OPENAI_API_KEY="your-internal-llm-key" \
  -e AI_REVIEW_MODEL="gpt-4o" \
  ai-review-platform:latest
3

Kích hoạt Webhook trên GitHub hoặc GitLab Monorepo

Vào mục Settings > Webhooks > Add Webhook của repository:

• Payload URL: http://your-server-ip:8080/
• Content type: application/json
• Secret: (Khớp với GITHUB_WEBHOOK_SECRET ở Bước 2)
• Trigger Events: Tích chọn Pull requests / Merge requests
4

Cơ Chế Baseline Quản Lý Nợ Kỹ Thuật (Clean-As-You-Code)

Hệ thống hỗ trợ file baseline.json. Đối với các dự án lớn đã có sẵn nhiều code cũ (legacy), các lỗi kiến trúc cũ sẽ được ghi nhận vào baseline và không chặn merge PR. Hệ thống chỉ chặn các lỗi MỚI xuất hiện trong Git Diff của PR hiện tại!
